# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Turn-based RPG built on Phaser 3 (forked from the `phaserjs/template-vite` template) with Vite, plain JavaScript ES modules, and Jest. Started from the gamedevacademy "turn-based RPG in Phaser 3" tutorial, which is why much of the code uses the old `new Phaser.Class({ Extends, initialize })` style and `var` instead of ES classes.

## Commands

- `npm run dev`: dev server on http://localhost:8080 (`dev-nolog` skips the template's `log.js` telemetry ping)
- `npm run build`: production build to `dist/` (`build-nolog` likewise)
- `npm run lint`: ESLint + `prettier --check`; `npm run lint:fix` to auto-fix
- `npm test`: Jest (jsdom + `jest-canvas-mock`, coverage always on, written to `coverage/`)
- Single test file: `npx jest src/tests/battle.test.js`; single test: `npx jest -t "part of test name"`

CI (`.gitlab-ci.yml`, from before the GitLab→GitHub migration) runs build, test and lint, then deploys from `main` via Docker Compose over SSH.

In-game controls: arrow keys move, Z confirms, X goes back, C opens the world menu.

In the dev server the game is reachable as `window.__game`, for driving it from browser automation (e.g. `__game.registry.set('floor', 7)` then restarting `WorldScene` to see a floor's mood).

Prettier style: no semicolons, single quotes, 2-space indent, `trailingComma: 'es5'`.

## Working style

- Work end to end without check-ins: make design decisions yourself and report them at the end.
- When you suggest an improvement that fits the current task, implement it instead of asking.
- Commit to the `claude` branch when a change is verified (game runs, lint passes). Never push.
- Only stop to ask when a choice would be hard to undo or changes the game's design direction.

## Architecture

**Entry**: `src/start.js` creates the `Phaser.Game` (1920×1080, WebGL only, arcade physics), registers every scene, installs the HD cameras and registers the text factories.

**Resolution** (`src/game/hd.js`): the game is laid out in the old 320×240 coordinate space but drawn at 1920×1080. Every camera zooms in 4.5× (`HD.ZOOM`) from its top left corner (origin 0, a patch on Phaser's `Camera.preRender` keeps `worldView` right). The 16:9 screen shows 426.67×240 layout units (`HD.VIEW_W`): menus, battles and the title keep their 320 wide layout, centered by scrolling every new camera `HD.OFFSET_X` (53.33) to the left, while backdrops and full-screen layers span `-HD.OFFSET_X` to `HD.VIEW_W - HD.OFFSET_X`. Objects pinned to the screen (scroll factor 0) are placed in screen units from 0 to `HD.VIEW_W`. The world camera follows the leader itself (`WorldScene.followCamera`), since Phaser's follow and bounds assume a centered origin. Art is painted at 4.5× its layout size: `hdTexture(texture)` marks a texture so it shows at its layout size with all its pixels, and `hdCanvas(scene, key, w, h, draw)` makes a canvas texture you draw on in layout units. Textures that aren't marked are drawn enlarged and blurry.

**Text** (`src/game/text.js`): `this.add.pixelText(x, y, text, size)` (centered), `colorText(x, y, text, cssColor, size)` and `gameText(x, y, fontKey, text, size)` (uncentered) make `GameText`, a Phaser `Text` drawn at screen resolution in Nunito (Cinzel from size 14), with an outline and a soft shadow. It keeps the old bitmap font API: `setFont(key)` picks a color by the old font keys (`pressstart` white, `pressstarty` gold for highlights, `pressstartg` grey, `pressstartb` blue, `pressstartr` red), plus `setMaxWidth` and `setCenterAlign`. Sizes are the old pixel font's, scaled up 1.35. The fonts ship in `public/assets/fonts` (declared in `index.html`) and `BootScene` waits for them before the title. Highlight text with `setFont('pressstarty')`, not `setTint`. Particle textures are generated in `BootScene` (`spark-fire`, `spark-ice`, `spark-magic`, `spark-white`, `spark-bolt`).

**Effects** (`src/game/fx/`, `Fx` in `index.js`) give the game its lighting and atmosphere. `Fx.look(scene, settings)` puts the look shader (`lookPipeline.js`) on a scene's main camera. It does point lights with smooth falloff (`Fx.addLight`, `Fx.pulseLight`; at most 8 at once, the nearest win; `lightBands` gives dithered bands instead), bloom that only spills into darker neighbors, color grading, tilt shift, vignette and screen flashes (`Fx.flash`). Lights count for less in daylight. `Fx.mood(floor)` picks a floor's light and weather: day, afternoon, dusk, night, then a violet abyss from floor 10, and rain on floors 2, 6 and every 4th after them. The map and battle build their cloud shadows, sun shafts, pollen, fireflies and rain from it. Menus and the HUD sit on a camera of their own (`Fx.uiCamera(scene, objects)`) so the look leaves them crisp. Objects added after that call go to the main camera unless moved with `Fx.toUi(scene, objects)`. Other pipelines: `Dissolve` burns away defeated enemies (`Fx.dissolve`), and `Wind` sways plants (`Fx.sway`; the image's place in the gust is passed through its tint, so don't tint swaying images). `Fx.creatureGlow` gives wisps and other glowing enemies a light. `Scenery` (`scenery.js`) builds larger scenery from these: the title backdrop's moonlit night (title and party selection) and `battleSky`, which repaints the daytime battle backdrop's sky for each mood (golden afternoon, dusk sun, night moon and stars, abyss, storm). Effect textures (`fx-glow`, `fx-shadow`, `fx-clouds`, `fx-mist`, `fx-ray`, `fx-rain`, `fx-mote`, `fx-shard`) are generated in `textures.js`. The look multiplies everything on its camera, so bright additive effects in daylight burn out quickly. Keep their alpha low.

**Menus share one look** (`src/game/ui.js`). `Ui.window(scene, x, y, w, h, { frame, fill })` adds a window of dark, slightly see-through blue glass with a thin gilded frame and gems on its corners (`frame: 'gold'` marks a highlighted card and glows inward, `fill: 'dusk'` is darker glass), painted at screen resolution into a texture cached per size. The glass shows what is behind it faintly, so hide text that sits under a window opened over it. `Ui.pointer(scene)` adds the gloved hand cursor. Call `pointer.pointAt(x, y)` every frame with the left edge of the highlighted entry so its nudge animates. Use these instead of `Graphics` boxes.

**Starting a scene without data reuses its previous start data** (Phaser only replaces `settings.data` when data is passed). Always pass data explicitly to scenes whose `init` reads it, e.g. `scene.start('PartyScene', { mode: 'VIEW' })`.

**Scene flow** (`src/game/scenes/`):
`BootScene` (loads assets, creates the shared `Inventory`) → `TitleScene` (load, or New Game → `PartySelectScene` where the player picks 2 starting heroes) → `WorldScene` (tilemap, random chests, enemy zones). The world map hides its tiles: the ground is painted for each floor when it loads (`paintGround`, `src/game/art/ground.js`), the tree tiles still block movement but painted trees stand on them (`plantTrees`), and walk-through decorations are scattered over the grass (`scatterDecorations`), all seeded by floor number. The leader is their battle sprite drawn small (`map-<hero>`) that hops a pixel or two while walking (`walk`, which lifts the sprite through its origin and keeps the collision body on the ground) and flips to face left; there are no walk cycle frames. Never rotate or squash pixel sprites, it smears their pixels. Map objects are depth sorted by the y position of their feet, and the HUD sits above them at `HUD_DEPTH` on its own camera (`hudCam`), which transitions fade along with the map (`fadeHud`). Static ground shadows are stamped into one render texture (`groundShadows`), so overlapping shadows don't darken each other. Touching an enemy zone runs `scene.switch('BattleScene')`. `BattleScene` runs `UIScene` (defined in the same `battle.js`) for menus. Its windows are low (from y 170) and reach into the wide screen's margins: the enemy list on the left, with the command window opening over it and the skill window rising over both, and the party's HP and MP gauges on the right (`PartyStatus`), where a gold band (`ui-rowglow`) marks the hero whose turn it is, as does a crystal over their head (`ui-marker`). At the start of each battle the units run onto the field (`enterUnits`) before the first turn. On victory it launches `VictoryScene`, whose windows open over the paused battle; it stops the battle scenes and wakes `WorldScene`. `WorldMenuScene` is launched over the world and opens `PartyScene`, `ItemScene` and `StatsScene`. `OptionsScene` is opened from the title and world menu: the caller pauses itself and passes `{ returnTo: key }`, and Options resumes it on close. Scenes that get reused hook the `wake` event (`this.sys.events.on('wake', ...)`) to reset their state, so code that re-initializes a scene has to go through the wake handler, not just `create`.

**Shared state lives in `this.registry`**, not on scene instances:

- `partyData`: array of plain hero stat objects (`type`, `hp`, `maxHp`, `mp`, `maxMp`, `xp`, `level`, `damage`, `magic`, `skills`, `equipment: { weapon, armor }`). This is the source of truth between battles.
- `inventory`: `[{ name, qty }]`, wrapped by `Inventory` (`src/game/inventory.js`), which is reachable as `this.game.inventory` and writes back to the registry on every change.
- `usedItem`: hands off which item was chosen between `ItemScene` and `PartyScene`.

`saveSystem` (`src/game/save.js`) saves `partyData` + `inventory` + a `version` to `localStorage` under the key `party_data`. When adding a hero stat, bump `SAVE_VERSION` and fill the stat in `migrateHero` so old saves still load. Audio settings are stored separately (`exlovia_settings`, `src/game/audio/settings.js`).

**Battle lifecycle**: `BattleScene.startBattle` builds hero sprites from `partyData` by looking up `heroesIndex[type]`, applies equipment bonuses (`Equipment.getBonus`, `src/game/equipment.js`), then spawns 2 random enemies from `enemiesIndex`. `placeUnit` stands each unit with its feet on a slot from `HERO_SLOTS` / `ENEMY_SLOTS`, so sprites of any height share a ground line. Nearer units are drawn in front, but always below the attack effects (depth 40+). Every unit has a ground shadow that follows it (`Unit.preUpdate`). Enemies with `sprite.hover` float above theirs and bob. Only enemies get an HP gauge under them. Each round, units act in speed order (`turnOrder`: `speed` + gear `speedBonus` + a 0-3 random roll, fastest first), drawn from `this.turnQueue`. Enemies have a 33% chance to use a random skill. Heroes and enemies both act through `performAction`, which plays the animation (`src/game/battleAnimations.js`) and applies damage in the animation's `onImpact` callback, so damage lands when the hit visually lands. After a win, `saveHeroData` applies level-ups (`xp >= level * 20` → `hero.levelUp()`), copies the sprite stats back into `partyData`, saves, and returns the level-ups for `VictoryScene`.

**Damage model** (`Unit.attack(target, skill)` / `takeDamage` in `units.js`): every attack is `physical` or `magic` (`skill.type`, basic attacks are physical with power 1). Physical damage = (`damage` + `attackBonus`) × `skill.power` − target `defense`. Magic damage = (`magic` + `magicBonus`) × `skill.power` − target `magicDefense`. A hit always does at least 1. Equipment bonuses are kept separate from base stats, so they're never saved into `damage`. `Unit.previewDamage(target, skill)` uses the same formula without dealing damage. The battle UI uses it to show yellow damage numbers over enemies while browsing skills or picking a target.

**Dungeon progression** (`src/game/progression.js`, `src/game/loot.js`): the stairs take the party one floor deeper (`registry.floor`, saved). On the way down the party recovers 50% HP/MP and the game autosaves, and the hero class not picked at the start joins on `Progression.recruitFloor` (3) at the party's average level. Enemy stats are written as floor 1 values, and `Progression.scaleEnemy` scales them per floor. Each enemy's `minFloor` decides when it appears (`enemyPool`/`pickEnemy`), and old types retire 3 floors later. Item `tier` decides when items show up in chests (tier 2 from floor 3, tier 3 from floor 6), and enemy drops roll each `{ item, chance }` entry. XP per level is `Progression.xpToNext`. Roaming map enemies show their type and lead the battle (`registry.encounter`). If every hero falls, `GameOverScene` returns to the title, so Continue loads the last save.

**Audio** (`src/game/audio/`) is synthesized with the Web Audio API; there are no audio files. `audioEngine.js` is the mixer (music/SFX buses with an SNES-style echo) and becomes a no-op where Web Audio is missing (jsdom). `Sfx.<name>()` plays effects. `Music.play(name)` plays songs from `songs.js`, which are written as a chord list plus a melody string. Each melody must add up to exactly 4 beats per chord, or it drifts out of time with the chords on every loop.

**Units and content registries**: `src/game/units.js` defines `Unit` (a sprite with HP/MP bars) → `Enemy` / `PlayerCharacter`. Content is data-driven through index modules, so adding content means creating a file _and_ registering it in its index:

- Heroes: `src/game/units/heroes/*.js` + `heroesIndex.js`. Each hero class has static `baseStats` (level 1) and `growth` (`{ hp, mp, damage, magic, speed }` per level), implements `levelUp()` (via `gainLevel(growth)`) and `checkSkills()` (filters its skill list by `levelReq`). `Party.createHero(type, level)` builds party data at any level. Static `description` is shown on the party selection screen, next to the hero's battle sprite.
- Enemies: `src/game/units/enemies/*.js` + `enemiesIndex.js`. Each file defines static `minFloor`, `sprite` (`{ texture, world, scale, worldScale, flipX, hover }`, `world` is the map texture, `<texture>-mini`) and `stats` (`{ name, hp, damage, magic, defense, magicDefense, xp, loot, skills }`) and passes them to `Enemy.call(this, scene, x, y, sprite, stats)`.
- Skills: `src/game/skills/<class>Skills.js` arrays of `{ name, description, power, mpCost, levelReq, target?, type, element? }`. The description is shown on the party menu's Skills page and in the battle message box while browsing skills, so keep it under about 34 characters + `skillsIndex.js`. Enemy skills use the same shape without `mpCost`/`levelReq`. `element` (`fire`/`ice`/`lightning`/`dark`) picks the spell's color, particles and sound (`ELEMENTS` in `battleAnimations.js`). The battle skill window lists names padded to 12 characters with the MP cost in a column after them, so keep names to 12 characters.
- Items: `src/game/items/*.js`. `itemIndex.js` collects every exported item automatically, keyed by its display name. Consumables use `healValue`/`manaValue` (applied in `PartyScene`). Equipment has a `slot` (`weapon`/`armor`) and any of `attack`, `magic`, `defense`, `magicDefense`. Every item needs a `tier` and a short `description` for the inventory detail panel.
- **All art is original.** Never add copyrighted or third-party art. Art may be image files, though so far it is all made in code; the only image files are exports for Tiled and the favicon (see `public/assets/CREDITS.md`).
  - **Pixel sprites** (`src/game/art/pixel/`) are the heroes and monsters, hand placed in the style of 16-bit JRPG battle sprites. Each sprite is written as rows of characters, one per pixel, with a legend of colors (`gridSprite(rows, legend, overlay)` in `grid.js`); outlines and shading are part of the rows, nothing is generated. `overlay` lists single pixels drawn on top (a blade on a slant, a staff), and `mirrored(halfRows)` builds symmetric front-facing creatures from their left half. Recolored monsters (frost wisp, blue dragon) are the same rows with another legend. Characters face right (heroes are flipped in game) with their feet on the bottom row, lit from the upper left. `pixel/index.js` makes a texture per key at a whole number of screen pixels per sprite pixel (NEAREST filtering): `battler-<hero>` and each monster's battle key at `BATTLE_PIXEL` (6), `map-<hero>` and `<monster>-mini` at 2, `title-<knight|mage>` at 10. Keep every display scale a whole number of screen pixels per sprite pixel (menus scale battlers by `n / BATTLE_PIXEL`). To review a sprite, draw it onto a canvas through the dev server at 10-20x with a pixel grid and fix single rows.
  - **Paintings** (`src/game/art/paintings/`) are the backdrops and map scenery. Each is a function returning SVG markup. `paintings/index.js` lists them with the texture keys they are loaded as and the size of each (1 = layout size): `BootScene` turns each into an SVG file that Phaser rasterizes at `HD.ZOOM` times that size, then marks it HD. A new picture needs a painting and an entry there.
  - Map props are drawn with `Painting` (`paint/svg.js`) in units of a tenth of a layout unit (a 24×30 tree has a 240×300 viewBox). Shapes are smooth curves through points (`blob`, `curve`, `stroke`), filled with gradients lit from the upper left (`linearAt`, `radialAt`). `part()` fills a shape, shades its lower right and lights its upper left edge with blurred strokes clipped to it, and outlines it in a dark shade of its color; `soft()` adds other blurred marks clipped to a shape; `glint()` adds a glossy highlight.
  - Backdrops (`battlefield.js`, `nightCastle.js`) are procedural SVG built with `seeded` random numbers (`paintings/scene.js`), as wide as the screen (`HD.VIEW_W`) with the 320 wide layout starting at `HD.OFFSET_X`. The scenes place them at `-HD.OFFSET_X`. The title's moon is at layout (276, 98), where `Scenery.moonlitNight` puts its halo.
  - **Drawn on canvases at boot or load**: the map's ground (`art/ground.js`, per floor), the logo (`art/logo.js`, Cinzel with a gold gradient), menu windows and the cursor (`ui.js`), sparks and effect textures. `art/world.js` only makes the blank `tiles` sheet the tilemap needs for collisions (1/3 grass, 2/4/5 trees, 6 bush) and lists `DECORATION_KINDS`.
  - To review art without running the game, import a painting module through the dev server and draw its SVG into an `<img>` at 4.5 times its size (or larger to inspect).

## Tests

**Do not write new unit tests or update existing ones** unless explicitly asked. Verify changes by running the game instead.

**The unit tests are outdated.** They no longer fully reflect the current game systems, so a failing test doesn't necessarily mean the code is wrong, and a passing one doesn't prove it's right.

Tests in `src/tests/` avoid booting Phaser: they call scene prototype methods with a hand-built fake `this`, e.g. `BattleScene.prototype.endBattleVictory.call(testScene)`, and `jest.mock` the index modules and `save.js`. Test names reference course requirement IDs (`REQ-x FR-y`).
